# 真實教室裝置驗收表

自動化測試已在無頭 Chromium 驗證完整流程；以下項目需在實際教室環境確認。

## 網路與 Supabase
- [ ] 教室 Wi-Fi 下 25～30 台平板同時連線，左下角顯示「已連線」而非「已連線（輪詢）」。若學校防火牆擋 WebSocket，系統會改用輪詢（每 2 秒），仍可上課但反應較慢。
- [ ] 擲骰後約 3 秒內學生平板出現代碼。
- [ ] 平板休眠／切換 App 後回到瀏覽器，畫面自動回到原階段。
- [ ] Supabase 免費方案的專案**閒置一週會暫停**；上課前到 Supabase 後台確認專案為 Active（暫停時按 Restore）。
- [ ] 學校網路若封鎖 Google Fonts，字體改用系統字型時版面仍正常。

## 學生平板（iPad／Android 平板／Chromebook）
- [ ] 相機掃 QR Code 能直接開啟報到頁，不需要輸入網址。
- [ ] 登入頁全螢幕不需捲動；輸入法跳出時「加入情報任務」仍按得到。
- [ ] 翻牌動畫流暢，翻牌後角色卡清楚；金框代碼在後排同學看不到的角度下仍清楚。
- [ ] Safari 私密瀏覽或關閉 Cookie 時的行為（localStorage 失效時，重整需請老師按「允許重新登入」）。
- [ ] 直向擺放的平板版面（卡片在上、指示在下）。
- [ ] **全螢幕（用課堂實際的平板逐一驗證）**：按「加入情報任務」即進入全螢幕；用手勢或按鍵退出後出現遮罩、看不到身分卡與代碼；按「回到全螢幕」恢復原畫面。
- [ ] iPad Safari、Android Chrome、Chromebook 各自的全螢幕行為；不支援時（如 iPhone Safari）出現「以一般畫面繼續」，仍可完成報到與翻牌。
- [ ] 臥底平板實際走一次：未翻牌（留白）→ 已翻牌（機密代碼不對你公開）→ 骰子跳動（維持）→ 代碼公布（機密任務）。
- [ ] 接鍵盤的平板／Chromebook：尚未翻牌就退出全螢幕，按 Tab、Shift+Tab 焦點只在遮罩按鈕，教師端翻牌人數不變；回到全螢幕親自翻牌後才加一。iPad 可開 VoiceOver 確認讀不到遮罩後的內容。
- [ ] 臥底已翻牌時退出全螢幕，請老師擲骰；公布後再按「回到全螢幕」，應直接看到「機密任務」。

## 教室大螢幕
- [ ] 實際投影機解析度（1024×768、1280×800、1920×1080）下文字、骰點、九格詞語不被裁切。
- [ ] 教室最後一排看得清楚集結人數、骰點與九格詞語；投影機色偏下藍／紅骰仍可分辨。
- [ ] 全螢幕按鈕在投影電腦的瀏覽器可用。

## 教師控制平板
- [ ] 23 人以上時六組名單一目了然，點選學生的觸控區夠大。
- [ ] 誤觸時的「作廢本輪」、「名單管理」流程符合老師習慣。
- [ ] 換一台裝置用「含金鑰的控制台連結」接手操作。

## 課堂流程
- [ ] 老師在公開情報卡前留給學生看平板的時間是否足夠。
- [ ] 四種結局各實際演練一次，確認大螢幕原因文字與現場結果一致。
- [ ] 連續多輪換人後，學生平板都正確回到卡背、身分與代碼重新分配。
